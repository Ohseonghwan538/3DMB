# 3D Memory Box 관리자 화면 명세서

- 문서 대상: 관리자(ADMIN) 콘솔 3개 화면
- 기준 와이어프레임: Figma `3D Memory Box - UI Wireframe (사용자 + 관리자)` > 페이지 "관리자 화면 (ADMIN)"
- 참고 문서: `FunctionTestScenario.tsv`, `UITestScenario.tsv` (에러 코드, 결함대장 D-001~D-006)
- 표기: 와이어프레임의 회원·용량·에러 건수는 **샘플 데이터**이며, 아래 "가정" 항목은 시나리오 파일에 없어 새로 정의한 내용입니다.

## 1. 화면 목록

| 화면 ID | 화면명 | 목적 | 주요 사용 권한 |
|---|---|---|---|
| ADM-001 | 회원 · 계정 관리 | 회원 조회, 상태 변경, 계정 잠금 해제, RBAC 권한 부여 | ADMIN 이상 (권한 부여는 SUPER_ADMIN) |
| ADM-002 | 추억 그룹 · 게시물 · 스토리지 관리 | 사용자 콘텐츠 모니터링 및 비공개/삭제, 이미지 저장소 관리 | MODERATOR 이상 |
| ADM-003 | 에러 로그 · 결함 추적 대시보드 | 도메인별 에러 빈도와 미해결 결함 조치 현황 파악 | ADMIN 이상 |

## 2. 공통 레이아웃 (1440px 기준)

| 영역 | 구성 |
|---|---|
| 좌측 사이드바 (240px) | 서비스명 "3D Memory Box", "ADMIN CONSOLE" 라벨, 메뉴 3개(에러·결함 대시보드 / 회원·계정 관리 / 추억·스토리지 관리). 현재 화면 메뉴는 강조 표시 |
| 상단 바 | 화면 제목(좌), 로그인한 관리자 계정과 역할 표시, 로그아웃(우) |
| 콘텐츠 영역 | 여백 24px, 카드/패널 간격 16px, 흰색 패널 + 회색 테두리 |

**공통 규칙**
- 관리자 로그인 후에만 접근하며, 권한이 부족한 메뉴는 숨기거나 비활성화합니다. (가정)
- 상태 변경, 삭제, 권한 부여, 잠금 해제 등 데이터를 바꾸는 모든 작업은 확인 모달을 거치고 **감사 로그**에 기록합니다. (가정)
- 상태 배지 색상: 정상/공개 = 녹색, 일시정지/보류 = 주황, 잠금/신고/삭제 = 빨강, 탈퇴/비공개 = 회색.

## 3. 권한(RBAC) 정의 (가정)

| 역할 | 설명 | ADM-001 | ADM-002 | ADM-003 |
|---|---|---|---|---|
| SUPER_ADMIN | 최고 관리자 | 전체 + 권한 부여 | 전체 | 전체 |
| ADMIN | 운영 관리자 | 조회, 상태 변경, 잠금 해제 | 전체 | 전체 |
| MODERATOR | 콘텐츠 운영 | 조회만 | 모니터링, 비공개/삭제 | 조회만 |
| USER | 일반 회원 | 접근 불가 | 접근 불가 | 접근 불가 |

## 4. ADM-001 회원 · 계정 관리

### 4.1 화면 구성

| 순서 | 영역 | 구성 요소 | 설명 |
|---|---|---|---|
| 1 | 요약 카드 | 전체 회원, 정상, 일시정지, 탈퇴, 계정 잠금(AUTH_002) | 상태별 회원 수. 카드 클릭 시 해당 상태로 목록 필터 (가정) |
| 2 | 검색/필터 | 검색창, 상태 Select, 권한(RBAC) Select, [조회] 버튼 | 아이디/이름 검색, 상태·권한 조건 조회 |
| 3 | 회원 목록 | 표 + 페이지네이션 | 좌측 메인 패널 |
| 4 | 회원 상세 · 조치 | 우측 패널(340px) | 목록에서 선택한 회원에 대한 조치 |

### 4.2 회원 목록 컬럼

| 컬럼 | 설명 | 비고 |
|---|---|---|
| 아이디 | 회원 `userId` | 로그인 아이디 |
| 이름 | 회원 이름 | |
| 상태 | 정상 / 일시정지 / 탈퇴 배지 | 잠금은 상태가 아닌 별도 플래그 |
| 권한 | SUPER_ADMIN / ADMIN / MODERATOR / USER | |
| 최근 로그인 | 마지막 로그인 일시 | |
| 로그인 실패 | 연속 실패 횟수. 5회 도달 시 "5 · 잠금" 빨간 배지 | AUTH_002 연동 |
| 작업 | [상세] 버튼, 잠금 계정은 [잠금 해제] 버튼 | |

### 4.3 회원 상세 · 조치 패널

| 요소 | 타입 | 동작 |
|---|---|---|
| 잠금 알림 박스 | 알림 | 잠금 계정 선택 시 표시. "AUTH_002 · 연속 로그인 5회 실패로 잠금", 잠금 시각 노출 |
| 계정 잠금 해제 | 버튼 | 확인 후 잠금 해제, 로그인 실패 횟수 0으로 초기화 |
| 계정 상태 변경 | Select (정상/일시정지/탈퇴) | 값 변경 후 [변경 사항 저장]으로 반영 |
| 관리자 권한(RBAC) | Select (USER/MODERATOR/ADMIN/SUPER_ADMIN) | SUPER_ADMIN만 활성화 (가정) |
| 변경 사항 저장 | 버튼 | 상태·권한 변경을 일괄 저장, 감사 로그 기록 |

### 4.4 업무 규칙

1. 사용자가 로그인에 **5회 연속 실패**하면 계정이 잠기고 AUTH_002가 발생합니다. 잠금 해제는 관리자가 이 화면에서 처리합니다.
2. 잠금 해제 시 연속 실패 횟수를 0으로 초기화합니다.
3. 상태가 **일시정지**인 회원은 로그인이 차단됩니다. **탈퇴** 회원은 목록에 남지만 로그인과 데이터 접근이 불가합니다. (가정: 탈퇴는 복구 불가)
4. 자기 자신의 권한 강등/상태 변경은 막습니다. (가정)
5. 마지막 SUPER_ADMIN은 강등할 수 없습니다. (가정)

### 4.5 예외/상태

| 상황 | 처리 |
|---|---|
| 조회 결과 없음 | "조건에 맞는 회원이 없습니다." 빈 상태 표시 |
| 저장 실패 | 오류 메시지 노출, 변경 전 값 유지 |
| 권한 없음 | 권한 Select 비활성화 및 안내 문구 |

## 5. ADM-002 추억 그룹 · 게시물 · 스토리지 관리

### 5.1 화면 구성

| 순서 | 영역 | 구성 요소 | 설명 |
|---|---|---|---|
| 1 | 요약 카드 | storage/original 사용량, storage/compressed 사용량, 전체 추억 그룹, 신고·검토 대기 | 사용량은 진행 막대와 사용률(%) 함께 표시 |
| 2 | 모니터링 패널 (좌) | 탭 [추억 그룹 / 사진 / 메모], 검색창, 표 | 사용자가 작성한 콘텐츠 모니터링 |
| 3 | 파일 상태 패널 (우, 420px) | 파일 상태 표, [재압축 실행], [고아 파일 정리] | 이미지 저장소 관리 |

### 5.2 추억 그룹 목록 컬럼

| 컬럼 | 설명 |
|---|---|
| 그룹명 | 추억 묶음 이름 |
| 소유자 | 작성 회원 아이디 |
| 사진 / 메모 | 그룹 내 사진 수, 메모 수 |
| 상태 | 공개 / 비공개 |
| 신고 | 신고 누적 건수. 1건 이상이면 빨간 배지 |
| 작업 | [비공개] (공개 상태일 때), [삭제] (Danger 버튼) |

### 5.3 동작

| 동작 | 설명 |
|---|---|
| 탭 전환 | 추억 그룹, 사진, 메모 단위로 목록 전환. 사진 탭은 썸네일, 메모 탭은 본문 미리보기 노출 (가정) |
| 비공개 처리 | 사용자 화면에서 숨기되 데이터는 보존. 필요 시 다시 공개로 복원 가능 |
| 삭제 | 확인 모달 후 삭제. 그룹 삭제 시 하위 사진·메모와 저장소 파일 처리 방식을 모달에서 안내 (가정: 파일은 정리 대상 큐로 이동) |
| 상세 보기 | 행 선택 시 우측 드로어에 썸네일, 메모, 신고 사유 표시 (가정) |

### 5.4 이미지 저장소 파일 상태

| 항목 | 설명 |
|---|---|
| 저장소 경로 | `storage/original` (원본), `storage/compressed` (압축본) |
| 컬럼 | 파일명 / 원본 크기 / 압축 크기 / 상태 |
| 상태 값 | 정상, 압축 누락(원본만 있음), DB 불일치(DB와 파일이 맞지 않음) |
| 재압축 실행 | 압축 누락 파일을 대상으로 압축본 재생성 |
| 고아 파일 정리 | DB에 연결되지 않은 파일을 확인 모달 후 정리 |

**관련 에러 코드**: 업로드 단계 오류는 UPLOAD_001~005 계열로 기록되며 ADM-003에서 발생 빈도를 확인합니다.

### 5.5 업무 규칙

1. 부적절 콘텐츠는 먼저 **비공개**로 전환해 확산을 막고, 확인 후 삭제를 권장합니다. (가정)
2. 사용량이 임계치(예: 80%)를 넘으면 카드에 경고 색상을 표시합니다. (가정)
3. 삭제와 정리 작업은 되돌릴 수 없으므로 반드시 확인 모달을 거칩니다.

## 6. ADM-003 에러 로그 · 결함 추적 대시보드

### 6.1 화면 구성

| 순서 | 영역 | 구성 요소 |
|---|---|---|
| 1 | 요약 카드 | 24시간 에러 발생, 미해결 결함, 조치 중/완료, 최다 발생 도메인 |
| 2 | 도메인별 에러 빈도 (좌) | 에러 코드별 가로 막대 차트, 도메인 합계 헤더 |
| 3 | 결함대장 조치 현황 (우, 400px) | 상태 누적 막대, 범례, 에러 코드 ↔ 결함 연결 목록 |
| 4 | 미해결 결함 목록 | 결함대장 표 (D-001~D-006) |

### 6.2 에러 코드 도메인

| 도메인 | 코드 | 비고 |
|---|---|---|
| AUTH | AUTH_001, AUTH_002, AUTH_003 | AUTH_001 로그인 불일치, AUTH_002 연속 실패 잠금, AUTH_003 아이디 중복 |
| UPLOAD | UPLOAD_001 ~ UPLOAD_005 | 사진 업로드/좌표/마커 관련 |
| GROUP | GROUP_001 | 추억 묶음 이름 중복 등 |
| ENGINE | ENGINE_001 ~ ENGINE_003 | 3D 지도 엔진. ENGINE_003은 타임아웃 시 2D Fallback |

> 각 코드의 상세 메시지는 `FunctionTestScenario.tsv`를 따릅니다.

### 6.3 차트 규칙

- 기간 기본값: 최근 24시간 (7일/30일 전환은 가정).
- 도메인별로 막대 색 농도를 구분하고, 막대 오른쪽에 발생 건수를 표시합니다.
- 도메인 헤더에 "도메인명 · 합계 건" 표시, 코드는 발생 건수 순 또는 코드 순 정렬 (기본: 코드 순).
- 막대 클릭 시 해당 에러 코드의 로그 상세로 이동 (가정).

### 6.4 결함대장 (D-001 ~ D-006)

| ID | 화면 · 요소 | 증상 | 관련 에러 | 상태 | 해결 방안 |
|---|---|---|---|---|---|
| D-001 | SCR-AUTH-001 · password | AUTH_002 CAPTCHA 입력 필드 작동 안 함 | AUTH_002 | 보류 | CAPTCHA 적용 or 미적용 결정 |
| D-002 | SCR-MAIN-001 · memory-group | 선택한 묶음이 아닌 사용자 전체 묶음 로드 | - | 보류 | 추억 묶음별로 기록 로드 |
| D-003 | SCR-MAIN-001 · btn-start-memory | 새 추억 저장 위치(지도)를 요구함 | GROUP_001 | 보류 | 이슈 기능 제거 |
| D-004 | SCR-MAIN-001 · file-photo | EXIF 좌표 대신 선택 위치를 DB에 저장 | UPLOAD_001 | 보류 | 사진 좌표 추출 후 카메라 제어 |
| D-005 | SCR-MAIN-001 · btn-save-memory | 카메라 고도가 높으면 마커 생성 안 됨 | UPLOAD_003~005 | 보류 | 업로드 이미지 좌표로 카메라 이동 |
| D-006 | SCR-MAIN-001 · btn-save-memory | 기본 마커(NO.png) 표시, 새로고침 필요 | UPLOAD_003~005 | 보류 | 업로드 이미지로 마커 표시 |

- 상태 값: 보류 → 진행 중 → 완료 (가정). 현재 6건 모두 "보류"이며 요약 카드와 누적 막대에 같은 수치를 사용합니다.
- 에러 코드 ↔ 결함 연결: AUTH_002→D-001, GROUP_001→D-003, UPLOAD_001→D-004, UPLOAD_003~005→D-005·D-006, D-002는 연결 에러 없음.
- 상태 변경 권한은 ADMIN 이상 (가정).
